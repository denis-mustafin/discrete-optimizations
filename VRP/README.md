# Решение задачи VRP

## Структура репозитория

- `main.cpp` - код текущего решения. Читает со стандартного ввода входной файл. В первой строке выводит счет решения на тесте, в каждой из следующих $v$ строк - количество людей, к которым едет очередная машина, и номера этих людей в порядке, в котором их надо посещать.
- `check.cpp` - код чекера. Аргументами командной строки получает пути до входного и выходного файлов. Проверяет корректность вывода и выводит его счет.
- `main` и `check` - скомпилированные (под Линукс) версии `main.cpp` и `check.cpp`
- `scored_data` - папка с оцениваемыми тестами
- `scored_data_output` - папка с ответами на оцениваемые тесты.

Пример использования чекера: `./check scored_data/vrp_421_41_1 scored_data_output/vrp_421_41_1.out`

## Решения

Счет решения в этой задаче - длина цикла, округленная вверх до ближайшего целого числа.

Глобально хочется сначала как-то разбить покупателей на V групп, с условиями на сумму весов и минимизируя какое-то приближение суммы длин циклов.

### 1: Жадное разбиение на множества + TSP

(Это по сути то же решение, что было в семестре, но с исправленными багами и добавленными костылями)

Разбиение на множества: Попытаемся найти какое-то разбиение, без оптимизации длин путей, но с каким-то интуитивным пониманием того, что они будут не очень большими. 

Набираем жадно по углу, начиная с перебираемого номера. 
Если что-то осталось в конце, то сначала пытаемся доложить в какую-то машину, если никуда не получилось, то пытаемся достать из какой-то машины элемент минимального веса, меньше нашего, но достаточно большой, чтобы после этого можно было положить туда наш элемент.
Такой костыль на всех тестах получает корректное разбиение.

Дальше для TSP написана динамика для размеров не более $20$ и решение задачи TSP для больших раазмеров. На практике всегда запускается динамика.
